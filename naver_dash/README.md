# 네이버 검색광고 팀장 대시보드

관리계정에 연결된 광고계정을 돌며 팀원별 현황과 경고를 모아 `output/naver_dash/dashboard-<기준일>.html` 로 만듭니다.
조회만 하며 광고계정은 변경하지 않습니다. 예외로 예산 소진 시각을 위해 보고서 생성 요청(POST /stat-reports)만 보냅니다(사용자 허용, 광고 설정 변경 없음).

## 점검 항목 (기준은 `collect.py` 상단 상수에서 조정)
1. 팀원별 담당 계정 수, 어제 총 광고비
   - 어제 광고비가 직전 7일 평균 대비 10% 이상 감소 (7일 일평균 1만원 미만 제외)
   - 이번 달 일평균이 전월 일평균 대비 ±50% 이상 차이
2. 비즈머니 부족: 잔액 ÷ 최근 7일 일평균 1일 미만 긴급, 3일 미만 주의
3. 광고 꺼짐(평소 소진 계정이 어제 0원)
4. 관리 경보: 아래 3가지 중 2개 이상이면 적색, 1개면 황색 (7일 일평균 1만원 미만 제외)
   - 구매완료 수익률 하락: 최근 7일 구매완료 수익률(구매완료 전환매출÷광고비)이 지난달보다 20% 이상 낮음
   - 광고비 하락: 최근 7일 일평균 광고비가 지난달 일평균보다 20% 이상 적음
   - 수정이력 없음: 캠페인·광고그룹 어디에도 7일 넘게 수정 기록 없음 (키워드·소재는 조회량이 커서 제외)

5. 이탈 위험: 최근 7일 일평균 광고비 30% 이상 감소 / 최근 30일 중 비즈머니 바닥(하루 마감 잔액 0 이하) 2일 이상 / 30일 이상 수정 없음 중 2개 이상
6. 예산 소진 캠페인: 최근 7일 하루 광고비가 현재 일예산의 95% 이상인 날 수와 평균 소진 시각. 시간대별 데이터는 `/stats` 로 안 나와(breakdown 무시됨) AD_DETAIL 보고서를 생성(POST /stat-reports, 광고 설정 변경 없음)해 그날 마지막으로 광고비가 나간 시간대를 소진 시각으로 봅니다. 보고서 비용 열은 `/stats` salesAmt 와 원 단위까지 같습니다. `--no-hours` 로 생략 가능

화면 기능
- 팀원 이름을 누르면 주소에 `?owner=이름` 이 붙어 그 팀원 계정만, 할 일 순서(긴급 → 적색 → 이탈 위험 → 황색)로 보입니다. 이 주소를 즐겨찾기하면 됩니다.
- 계정 표에서 광고주 앞 ▸ 를 누르면 캠페인별 최근 7일 vs 지난달 광고비·구매 ROAS(구매매출 감소가 큰 순)와 예산 소진 캠페인이 펼쳐집니다.
- 팀원 카드에 담당 계정 중 광고비 집행·휴면(어제·7일·이번 달·지난달 모두 0원) 수를 표시합니다.

## 환경변수 (코드·채팅에 키를 절대 넣지 않음 — 공개 저장소)
- `NAVER_API_KEY` : API 라이선스(Access License)
- `NAVER_SECRET_KEY` : 비밀키(Secret Key)
- `NAVER_CUSTOMER_ID` : 키를 발급한 계정의 Customer ID

발급 위치: searchad.naver.com → 도구 → API 사용 관리

## 팀원 매칭
`team.example.json` 을 `team.json` 으로 복사해 채웁니다(커밋 제외).
`scope` 에 팀 공용 관리계정 번호를 넣으면 거기 연결된 광고계정만 수집합니다(다른 팀 계정 제외). 특정 계정을 빼려면 `exclude` 에 SA Customer ID 를 넣습니다. 담당자는 아래 순서로 먼저 맞는 규칙을 씁니다.
1. `accounts` : SA Customer ID → 팀원 (개별 예외)
2. `managers` : 관리계정 번호 → 팀원. 팀원별 관리계정에 연결된 광고계정을 그 팀원 담당으로 봅니다. 번호는 `check_access.py` 1) 에 나옵니다.
3. `members` : 구성원 네이버ID → 팀원. API 제약상 키 발급 계정이 **직접 구성원인** 광고계정에서만 조회됩니다.

어디에도 안 맞으면 `fallback`(기본 "미지정")으로 표시됩니다.

### 실제 키로 확인한 API 동작 (2026-10)
- `/ad-accounts/{no}/members` : `X-Customer` 에 키 발급 계정 ID 를 넣어야 하고, 관리계정 하위 광고계정은 어느 ID 로도 403. 그래서 팀원 구분은 관리계정 단위(`managers`)가 기본입니다.
- 같은 광고계정이 팀 공용 관리계정과 개인 관리계정에 중복 연결돼 있어 수집 시 customerId 로 합칩니다.
- `/stats` 는 `{"data":[{"id","salesAmt",...}]}` 형식이며, 기간 내 실적이 없는 캠페인은 행이 빠집니다.
- 광고비(`salesAmt`)는 광고주센터 실적 리포트의 유상실적 × 1.1(VAT 포함)과 일치합니다(6팀 계정 23개, 2026-10-02~08 대조). 단, 아래는 차이가 납니다.
  - 빠짐: 성과형 DA(GFA)·ADVoost 쇼핑, 브랜드검색 계약 금액
  - 포함: 무상 캐시로 소진한 금액
- `managerAccount.childAdAccountCount` 는 null 로 옵니다.
- 대시보드의 광고주·비즈머니·마지막 수정일을 누르면 광고센터(`ads.naver.com/manage/ad-accounts/{adAccountNo}/...`)의 계정 대시보드·비즈머니, 그리고 마지막으로 수정된 캠페인·광고그룹 화면으로 이동합니다. 관리계정을 거쳐 접근하는 계정이라 주소에 `?accessManagerAccountNo={관리계정번호}` 를 붙입니다(없으면 "접근 권한이 없습니다"). 그 관리계정 권한이 있는 네이버 ID 로 로그인돼 있어야 합니다.
- 변경이력 조회 API 는 없습니다. 캠페인·광고그룹의 `editTm`(UTC, 마지막 수정 시각)으로 판단합니다. 캠페인 `editTm` 은 하위 그룹 수정을 반영하지 않아 그룹까지 모두 봅니다.
- 수익률·매출·전환수는 `/stats` 의 `purchaseConvAmt`·`purchaseCcnt`(구매완료)를 씁니다. `convAmt`·`ccnt` 는 장바구니·회원가입 등 모든 전환 합계라 쓰지 않습니다. 계산값은 네이버 `purchaseRor` 와 같습니다.
- `/manager-accounts` 에는 키 발급 네이버ID가 구성원인 관리계정만 나옵니다. 팀원 관리계정이 안 보이면 그 관리계정에 키 발급 ID를 구성원(조회 권한 이상)으로 추가해야 합니다. 하위 관리계정의 광고계정은 상위 관리계정 목록에 함께 나오지만 어느 하위 관리계정 소속인지는 나오지 않습니다.

## 실행
```bash
python3 naver_dash/check_access.py         # 1) 키로 무엇이 조회되는지 먼저 점검
python3 naver_dash/collect.py --limit 3    # 2) 3개 계정만 시험 수집
python3 naver_dash/collect.py              # 3) 전체 수집
python3 naver_dash/collect.py --demo       #    키 없이 가상 데이터로 화면 확인
```

## 회사 PC 에서 매일 자동 실행 (Claude 크레딧 소모 없음)
1. 파이썬 3 설치 (python.org, 설치 시 "Add to PATH" 체크). 추가 패키지는 필요 없습니다.
2. 이 저장소를 회사 PC 에 내려받고(`git clone`) `naver_dash/team.json` 을 둡니다 (커밋 금지 파일). `run_daily.bat` 이 실행 때마다 `git pull` 로 최신 코드를 받습니다.
3. API 키를 **사용자 환경변수**로 등록 (명령 프롬프트, 키 값은 직접 입력. 파일에 적지 않음):
   ```
   setx NAVER_API_KEY "..."
   setx NAVER_SECRET_KEY "..."
   setx NAVER_CUSTOMER_ID "..."
   ```
4. 작업 스케줄러에 매일 07:00 등록:
   ```
   schtasks /Create /SC DAILY /ST 07:00 /TN "6팀 대시보드" /TR "\"C:\경로\naver_dash\run_daily.bat\""
   ```
5. 결과: `output/naver_dash/dashboard.html` 이 매일 새 데이터로 바뀝니다(파일 이름 고정). 실행 기록은 `output/naver_dash/run.log`.
6. 팀원에게 링크 나누기: 회사 PC 에서 `naver_dash/serve.bat` 을 켜 두면 사내망에서
   `http://<회사 PC IP>:8080/dashboard.html?owner=박송희` 처럼 열립니다. (윈도우 방화벽 허용 필요, 사내망 누구나 볼 수 있음)

수집 시간 줄이기 (기본 적용)
- 4개 계정 동시 수집 (`--workers`, 호출 한도 오류가 나면 줄임)
- 휴면 계정은 전날 결과를 재사용하고 최근 14일 광고비만 확인, 상세 수집은 7일마다 (`--full` 이면 전부 상세)
- 예산 OFF 시간대 보고서는 날짜별로 `output/naver_dash/hourly/` 에 저장해 두고, 매일 어제 하루치만 새로 만듦 (15일 지나면 삭제)

## 팀원(신입) 추가
- 신입 관리계정이 「6팀 홍길동」 이름으로 생기면 `team.json` 의 `managerPrefix: "6팀 "` 규칙으로 **자동 인식**됩니다.
- 단, **API 키 발급 네이버 ID 를 그 관리계정 구성원(조회 권한 이상)으로 추가**해야 API 에 보입니다. 안 하면 그 신입 계정은 `fallback` 담당으로 잘못 잡힙니다.
- 확인: `python3 naver_dash/check_access.py --limit 0` → 1) 목록에 「6팀 홍길동」이 보이면 OK.

## 성과 진단 덱 툴용 보고서 자동 받기 (`deck_export.py`)
신입이 다차원 보고서를 종류·기간별로 20개 넘게 받던 일을 대신합니다.
```
python3 naver_dash/deck_export.py --account 1736106 --start 2026-06-01 --end 2026-09-30
```
- 결과: `output/naver_dash/deck_export/<계정>_<기간>/` 에 매체·소재, 검색어, 성별, 연령대, 요일·시간대 CSV 와 쇼핑검색 소재목록 TSV.
  이 폴더 파일을 덱 툴 '자료 올리기'에 통째로 끌어다 놓습니다. 스마트스토어 리뷰·상품목록은 지금처럼 직접 받습니다.
- API 보고서는 **하루치씩만** 만들어집니다(기간 지정 4가지 시험 → 첫날만 나오거나 형식 오류). 그래서 날짜별 원본을
  `output/naver_dash/reports/` 에 쌓아 두고 한 번 받은 날짜는 다시 받지 않습니다.
- 검증(sbskorea98, 2026-09-01~03): 노출·클릭·광고비·구매완료 수·매출이 `/stats` 계정 합계와 일치.
- 한계: 매체는 번호로만 옵니다(이름 사전 API 없음). 파워링크 검색어는 전환이 API 에 없어 0 으로 들어갑니다.
